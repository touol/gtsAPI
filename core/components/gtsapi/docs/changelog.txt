Changelog for gtsAPI.
1.1.6-beta
==============
- Кода 1.1.5 не менялось: сборка выпущена заново, чтобы не путать версии
  после публикации. Описание поправлено в одном месте - собранный PVTables
  идёт внутри пакета, ставить его отдельно не нужно.

1.1.5-beta
==============
- Ещё три PHP warning в чтении таблиц на PHP 8: неинициализированный total
  (без setTotal), обращение к setTotal без проверки и к ключу field у поля,
  где имя берётся из ключа конфига. Поведение прежнее, лог чистый.
- Нет каталога модели у пакета - больше не зовём addPackage: у классов ядра
  (пакет 'modx') его и не бывает, а xPDO писал в лог «Path specified for
  package modx is not a valid directory» на каждый вызов.
- Доп. поля работают с классами ядра MODX (modResource и прочие). Раньше такой
  класс молча выпадал из синхронизации: «родные» поля брались только из xml-схемы
  компонента, а у ядра отдельного файла схемы нет. Теперь, если схемы нет,
  поля спрашиваются у самой модели.
- На MODX 3 доп. поля доезжают до карты классов. Там $modx->map - объект
  xPDOMap, а классы лежат под полным именем (MODX\Revolution\modResource):
  плагин писал в $modx->map['modResource'], то есть в никуда, и xPDO о доп. поле
  не знал. Ключ теперь берётся через loadClass(), а запись карты идёт целиком,
  а не через изменение вложенного элемента.
- Удаление ПОСЛЕДНЕГО динамического поля таблицы наконец убирает колонку.
  Таблица с опустевшим списком полей выбрасывалась из обхода, и её колонка
  висела в базе навсегда - «Снести колонки удалённых полей» её не видела.
- Снос колонок не трогает таблицу, схему класса которой прочитать не удалось:
  раньше в таких случаях кандидатами на удаление считались ВСЕ её колонки.
- Динамические доп. поля заработали на MODX 3. Копию генератора под MODX 3
  (manager3.class.php) удалили: это был форк основного файла, отставший
  на несколько правок - NULL распознавался только по строке 'true',
  SHOW FULL COLUMNS звался с именем класса вместо таблицы, alterField писал
  MODIFY вместо CHANGE. Теперь реализация одна, а предок (xPDOGenerator)
  выбирается на лету по доступному xPDO. Проверено полным циклом на обеих
  версиях: колонка создаётся, тип меняется, колонка снимается, таблица
  возвращается к исходному виду.
- На MODX 3 справочник допполей больше не сыплет в лог по три ошибки на вызов
  («Undefined variable $loaded», «Could not load gtsAPIManager class»).
  Сообщение одно и по делу: динамические доп. поля на MODX 3 пока
  не поддерживаются, колонки таблиц не изменялись.
- Убрана ругань при установке: gtsAPIFile поднимал сервис gtsAPI по неверному
  пути (model/gtsapi/ вместо model/), из-за чего каждое создание файлового
  объекта писало «Could not load class: gtsAPI from gtsapi». Сервис при этом
  нигде не использовался - вызов удалён.
- Зависимости ищутся у ВСЕХ подключённых провайдеров, а не только у указанного
  в конфиге: pdoTools живёт на modx.com, наши пакеты - на modstore, и поиск
  в одном репозитории давал «не найден» на ровном месте. Заодно резолвер
  перестал писать в лог пустую строку вместо сообщения об ошибке.
- Починена чистая установка: справочные данные (списки выбора для админки)
  писались раньше, чем создавались таблицы, и установка сыпала
  «Table 'modx_gtsapi_selects' doesn't exist». Резолверы выполняются
  в алфавитном порядке, а файл назывался data.php и шёл первым - переименован
  так, чтобы идти после tables.php. На сайтах, где 1.1.4 уже установлена,
  списки выбора создадутся при обновлении.

1.1.4-beta
==============
- Установщик пакетов (/api/package) умеет ставить пункты меню менеджера:
  в PVExtra появился _build/configs/menus.js, формат тот же, что у сниппетов.
  Своего контроллера пакету заводить не нужно - пункт вешается на страницу
  gtsAPI, а что показать, описывается в &config.
- Своя страница в админке. Контроллер gtsAPI разбирает параметр меню &config
  и вызывает указанные в нём сниппеты:
      &config={"PVTabs":{"tabs":{"DocType":{"title":"Типы","table":"DocType"}}}}
      &config={"mixVue":{"app":"pvsklad","config":{"module":"BarcodeDocs"}}}
  Ключ — имя сниппета, значение — его параметры; вместо JSON можно указать имя
  системной настройки, в которой он лежит. Так любой компонент выводится
  в меню MODX без собственного контроллера.
- Таблицы самого gtsAPI описаны синтаксисом gtsAPI (_build/elements/
  gtsapipackages.php) и ставятся резолвером, как у любого другого пакета.
  Раньше админка gtsAPI была ~1000 строк JSON на синтаксисе getTables внутри
  системной настройки. Все её действия перенесены: генерация полей и правил,
  экспорт-импорт таблицы, правила и селекта, копирование, подтаблицы связей.
  Пункт меню на старую админку убран, сам конфиг gtsapi_admin остаётся
  в настройках как страховка.
- Библиотека PHPExcel больше не берётся из чужого пакета: gtsAPI ищет её
  по настройке phpexcel_path, затем в пакете PHPExcel и только потом
  в старой копии внутри getTables (для сайтов, где пакет ещё не поставлен).
  Пакет PHPExcel добавлен в зависимости.
- Сниппет mixVue понимает config строкой JSON. Массив приходит только из Fenom,
  а обычный вызов [[!mixVue? &config=`{"module":"TLAll"}`]] отдаёт строку —
  раньше она молча игнорировалась и приложение стартовало без конфигурации.
  Неразобранный JSON теперь пишется в лог с текстом ошибки.
- Триггеры справочника допполей продублированы в формате gtsAPI
  (triggerAddFieldsAPI). Ключ gtsfunction срабатывает ТОЛЬКО в админке
  getTables, поэтому в новой админке правка поля или группы не приводила
  колонки таблиц в соответствие. Старый триггер помечен @deprecated -
  на удаление вместе с интерфейсом на getTables.
- Генерация правил (gen_rules) спрашивает пакет своей формой, а не чанком
  модалки getTables.
- Разбор id действия вынесен в rowId(): gtsAPI шлёт поля строки как есть,
  а ключ trs_data - формат getTables, помечен на удаление.
- Обновлён встроенный бандл PVTables (0.2.1): модальная форма может приходить
  в ответе действия, в том числе несколькими шагами подряд.
- Экспорт-импорт таблицы, правила и селекта отдаёт форму для PVTables,
  а не готовый HTML модалки getTables: в интерфейсе на PVTables старое окно
  открывалось пустым и ничего не сохраняло. Собранный PVTables идёт внутри
  пакета, отдельно ставить ничего не нужно.
- Импорт (save_table / save_rule / save_select) больше не прогоняется через
  санитайзер MODX: он выкусывал из JSON теги вида [[…]], которые законно
  встречаются в свойствах таблиц, и конфигурация сохранялась битой.
  Действия доступны только администратору.
- getTables убран из зависимостей: админка переехала на свой контроллер
  и PVTables, а библиотека Excel вынесена в пакет PHPExcel. Там, где getTables
  уже стоит, ничего не ломается - интерфейсы уживаются.
- Убраны PHP warning на PHP 8 в контроллерах таблиц: обращения к hide,
  sortField, multiSortMeta, showLog и к никогда не заполняемому ключу действий
  сделаны безопасными. Поведение прежнее, в логе перестало быть шумно.

1.1.2-beta
==============
- Резолвер данных больше не читает data.json без проверки существования:
  пакет может не везти справочных данных вовсе, и это не повод писать

1.1.1-beta
==============
- Резолверы зависимостей научились читать ответ провайдера на MODX 3: там
  provider->request() отдаёт PSR-7 объект, а не modRestClient со свойством
  ->response. Из-за этого на MODX 3 поиск пакета возвращал пустоту и выглядел
  как "пакета нет у провайдера" - ни одна зависимость не устанавливалась.
  Касалось обоих резолверов: собственного (pdoTools, getTables) и того,
  что уезжает в PVExtra-пакеты.
- Внятная диагностика вместо общего "не найден у провайдера": ищем у всех
  подключённых провайдеров; отдельно сообщаем, если указанный в конфиге
  провайдер на сайте не подключён, и что с этим делать; отдельно - если пакет
  найден, но не скачался при пустых логине и ключе провайдера.

1.1.0-beta
==============
Первый релиз после 1.0.15-beta (модстор, 16.09.2025): 304 коммита за 11 месяцев.

Установка пакетов
-----------------
- Резолвер зависимостей: недостающие пакеты доустанавливаются ПЕРЕД установкой
  самого пакета - поиск у провайдера или прямая ссылка на transport.zip.
  Список задаётся в _build/configs/dependencies.js.
- Динамические доп. поля применяются прямо при установке, без ручного прогона.
  Снос колонок вынесен в отдельную команду админки "Снести колонки удалённых полей".
- Поле, добавленное в схему, создаётся с ПЕРВОЙ установки (раньше нужна была вторая).
- ALTER выполняется только при реальном расхождении колонки с описанием: установка
  gtsShop - с 573 перестроек таблиц до одной, сборка пакета 21.6 с против 7.8 с.
- Ключевые колонки (id, первичный ключ) и динамические доп. поля не удаляются
  ни при каких условиях; чужая таблица класса-наследника не изменяется.
- Конфиги страниц (resources.js) и данных (data.js) умеют раскладку по сайтам:
  ставится только то, что относится к текущей инсталляции.
- Резолверы прав и групп пользователей: пакет привозит шаблон политик MODX,
  своих групп не создаёт.

Журнал и версии записей
-----------------------
- gtsAPILog: лог действий на стороне сервера с настраиваемым сроком хранения
  и ежесуточной чисткой, вкладка в админке.
- TableVersionTrait: версии записи и откат к предыдущему значению
  (действия versions/restore_version, флаг save_version_row).
- Логирование UniTree и диспатч триггеров целевого класса на create/update/delete.

Таблицы и интерфейс (бандл PVTables 0.2.0)
------------------------------------------
- Таблица переехала на TanStack, форк PrimeVue DataTable удалён: виртуальный скролл,
  автоподгонка и ручной ресайз колонок, выбор видимых колонок, закреплённая колонка
  действий, sticky-заголовки.
- Редактирование: inline и попап, выделение диапазона ячеек как в Excel
  с суммированием, автодополнение в текстовых ячейках, undo/redo для CRUD.
- Фильтры: серверные и клиентский чеклист с разделением в интерфейсе, пустые даты,
  datetime со своими режимами, фильтры из URL с namespace таблицы.
- Файлы: тип ячейки file с превью и выбором, съёмка с камеры, браузер файлов,
  распределение загрузок по год/месяц, многостраничный снимок документа в PDF.
- Мобильный режим: карточки вместо таблицы, роли полей, флаги mobile_only/desktop_only.
- Точечное обновление строк (rows_delta) с подписями автокомплитов и сохранением
  раскрытых дочерних строк.

Экспорт и печать
----------------
- Excel: TZ-safe даты, html в текст, настраиваемые ширины колонок и скрытие
  колонки через col_widths, форматирование decimal, datetime, пустых ячеек.
- Печать: PVPrintAction в строке, компактный режим, классы col-<field> для стилей.

Исправления
-----------
- Безопасность: правки по аудиту API, удалены небезопасные скрипты
  copy_package.php и rename_it.php.
- gtsAPILog: поля переименованы из зарезервированных слов MySQL
  (table_name -> log_table, action -> log_action).
- Пустая дата с фронта сохраняется как NULL, а не режется.
- Триггеры before-read получают правило и поля по ссылке и могут менять запрос.
- Битый UTF-8 в теле запроса больше не ломает JSON-кодирование.
- Множество мелких фиксов CRUD, фильтров, деревьев и автокомплитов.
